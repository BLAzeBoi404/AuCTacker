# AucTracker — запуск 24/7: лимиты, git, хостинг, пассивный режим

## Если лот есть в игре, но уведомление ещё не пришло

AuCTracker получает активные лоты только из официального EXBO EAPI. Игра и EAPI обновляются не одновременно. Во время реального теста 10.09.2026 обычный «Браслет» +0 за 6 000 000 ₽ появился в игре в 15:52:20 UTC, но EAPI начал возвращать его примерно в 16:03 UTC — задержка составила около 11 минут. AuCTracker создал совпадение сразу после появления лота в EAPI.

Проверяйте по порядку:

1. **Админ → Telegram → Тест.** Если тест пришёл, бот и чат работают.
2. **Трекеры → Проверить сейчас.** Карточка после обновления показывает время проверки, сколько лотов отдал EXBO и сколько подходит под условия.
3. Если `EXBO: N лотов · подходит: 0`, а лот виден в игре — EAPI его ещё не передал. Ускорить официальный источник со стороны сайта нельзя.
4. Проверьте регион, редкость и заточку. Поле «Цена от» означает `цена >= значение`, поле «Цена до» — `цена <= значение`.
5. Новый трекер сначала запоминает текущие лоты. В обновлённой версии бот дополнительно присылает стартовый отчёт с количеством лотов и совпадений.

Ошибка сети/авторизации EXBO теперь отображается как ошибка, а не как пустой аукцион. На странице предмета явно указан источник данных — EXBO EAPI.

**Безопасность:** секрет EXBO ранее присутствовал в присланном исходнике. После установки этой версии перевыпустите `EXBO_CLIENT_SECRET` в кабинете EXBO и замените значение в Render Environment. В коде этой версии секретов нет.

## 0. Хватит ли бесплатного Neon? Коротко — да, с запасом

У тебя на скрине лимиты Free: Compute 0/100 CU-hrs, Storage 0/0.5 GB, Network 0/5 GB.
Наша база крошечная, тяжёлые данные вообще мимо неё идут.

**Storage 0.5 GB = 512 МБ. Нам надо ~10 МБ.**
Замер на живой базе: вся база 8.5 МБ, из них таблица предметов (2329 штук) — 0.8 МБ,
остальные таблицы (трекеры, уведомления, чаты, настройки) — по 16–32 КБ.
Трекеры и уведомления — это строки по 200–300 байт. Даже 50 трекеров и 300
уведомлений добавят меньше мегабайта. Забить 512 МБ у тебя не получится при всём желании.

**Network 5 GB в месяц.** Цены и картинки не хранятся в Neon: лоты идут с EXBO EAPI, иконки — с GitHub. Через базу проходят трекеры, настройки и короткая история уведомлений. Реальный расход зависит от числа пользователей и частоты проверок — следите за Neon → Monitoring.

**Compute 100 CU-hrs — главное ограничение бесплатного Neon.** Neon засыпает только после 5 минут полного отсутствия SQL-запросов. Опрос каждые 1–5 минут не даёт базе гарантированно уснуть. Минимальный compute 0,25 CU за непрерывные 30 дней расходует примерно `0,25 × 24 × 30 = 180 CU-часов`, что больше бесплатных 100.

- Для тестового бесплатного режима используйте внешний cron раз в **10–15 минут** и контролируйте Compute. Уведомление получит дополнительную задержку.
- Для действительно постоянной проверки каждую минуту нужен подходящий платный тариф Render/Neon или постоянно работающий VPS с PostgreSQL.
- Даже частая проверка сайта не убирает задержку самого EXBO EAPI: в реальном тесте она составила около 11 минут.

Бесплатный Neon с большим запасом подходит по объёму данных, но бесплатный Compute не является гарантией непрерывного 24/7.

## 1. Заливаем код на GitHub (разово, 10 минут)

У тебя код уже лежит в папке (на скрине: `E:\Downloads\stalzone-auction-tracker-development`,
внутри `src`, `package.json`, `HOSTING.md`). GitHub нужен как мост:
Render умеет ставить сайт только из GitHub, напрямую с твоего ПК — нет.

Делаем всё в том чёрном окне «Терминал» внизу VS Code (у тебя там PowerShell).

**Шаг 1. Проверь git.** Вставь в терминал и нажми Enter:

```powershell
git --version
```

Если показало версию (например `git version 2.39.5`) — иди дальше.
Если ругается — поставь с git-scm.com, при установке везде жми Next,
потом закрой и открой VS Code заново.

**Шаг 2. Скажи git кто ты (один раз на этом ПК):**

```powershell
git config --global user.name "Alexandr"
git config --global user.email "твоя-почта@gmail.com"
```

Почту впиши ту же, на которую зарегистрирован GitHub.

**Шаг 3. Создай пустой репозиторий на GitHub.**
Зайди на github.com → справа вверху **+** → **New repository**.
- Repository name: `auctracker` (или как хочешь, латиницей без пробелов)
- **Public или Private — на выбор**, сайт всё равно будет работать
- НЕ ставь галочки «Add a README», «Add .gitignore» — репозиторий должен быть пустым
- Нажми **Create repository**. Откроется страница с адресом вида
  `https://github.com/ТВОЙ-НИК/auctracker.git` — скопируй его.

**Шаг 4. Залий код.** В терминале VS Code, по одной строке (вставляй → Enter,
жди → следующую). Первая строка переходит в твою папку:

```powershell
cd E:\Downloads\stalzone-auction-tracker-development
git init
git add .
git status
```

После `git status` посмотри список: там должны быть `src/`, `package.json`,
`render.yaml`, `HOSTING.md` и прочие. Там **не должно быть** `.env`
(файл с секретами). Если `.env` в списке есть — стоп, напиши мне,
будем чинить (его пушить нельзя).

Дальше:

```powershell
git commit -m "AucTracker: первый запуск"
git branch -M main
git remote add origin https://github.com/ТВОЙ-НИК/auctracker.git
git push -u origin main
```

Замени `ТВОЙ-НИК/auctracker` на свой адрес из шага 3.

GitHub спросит логин. Пароль от аккаунта НЕ подойдёт — нужен токен:
GitHub → аватарка → **Settings** → слева внизу **Developer settings** →
**Personal access tokens** → **Tokens (classic)** → **Generate new token (classic)**.
Галочка только **repo**, срок — 90 days. Скопируй токен (он показывается один раз)
и вставь вместо пароля. Логин — твой ник на GitHub.

Если всё хорошо — увидишь `Branch 'main' set up to track...`.
Обнови страницу репозитория в браузере: файлы должны появиться.

**Как заливать изменения потом** (когда поменяешь код): всего 3 строки
в том же терминале из той же папки:

```powershell
cd E:\Downloads\stalzone-auction-tracker-development
git add .
git commit -m "что поменял"
git push
```

Render после каждого `git push` сам пересоберёт сайт за 2–3 минуты.
Ничего больше нажимать не надо.

## 2. Сайт на Render (бесплатно)

1. Зайди на **render.com** (войди через тот же GitHub).
2. **New → Web Service** (или **New → Blueprint**, если хочешь в 2 клика —
   файл `render.yaml` уже лежит в проекте) → выбери репозиторий `auctracker`.
3. Настройки:
   - Build Command: `npm install && npm run build`
   - Start Command: `npm start`
   - Plan: **Free**
4. Вкладка **Environment**, добавь 3 переменные (кнопка Add Environment Variable):
   - `DATABASE_URL` — pooled-строка из Neon. У тебя на скрине проект AuCTracking:
     слева **Connect** → включи **Pooled** → скопируй строку вида
     `postgresql://user:pass@ep-xxx.neon.tech/db?sslmode=require`.
     Именно pooled (с `-pooler` в адресе), иначе Render съест все соединения.
   - `EXBO_CLIENT_ID` — `4062`
   - `EXBO_CLIENT_SECRET` — твой секрет EXBO
5. Нажми **Create Web Service**. Первая сборка идёт 3–5 минут.
   Когда статус станет **Live** — открой адрес вида `xxx.onrender.com`.
   Таблицы в Neon создадутся сами при первом запуске, `drizzle-kit push`
   руками делать не надо.
6. Проверка: открой `xxx.onrender.com/api/health` — должно быть `{"ok":true}`.

Про сон Render: бесплатный сайт засыпает после 15 минут без посетителей,
первое открытие после сна висит ~50 секунд. Это нормально, дальше летит.
Пункт 3 ниже будит его автоматически.

## 3. Пинг на cron-job.org (чтобы работало с выключенным ПК)

Без этого пункта сайт спит, проверки стоят, Telegram молчит. С ним —
сайт просыпается сам каждые пару минут. Настройка один раз, 5 минут.

1. Зарегистрируйся на **cron-job.org** (бесплатно), войди.
2. **Create cronjob**.
3. **Title**: `auctracker` (что угодно).
4. **Address (URL)**: открой свой сайт → **Настройки → Фоновый трекинг** →
   скопируй готовый URL вида
   `https://xxx.onrender.com/api/cron/check?secret=...` (кнопка-копия рядом)
   и вставь целиком, вместе с secret. Без secret будет 401 — так и должно быть,
   чужой этот адрес дёргать не сможет.
5. Расписание: **каждые 2–3 минуты**.
6. Сохрани. Как понять, что работает: на сайте в Настройках строка
   «Последняя проверка» обновляется каждые пару минут, даже когда сайт закрыт.

## 4. Чеклист пассивного режима (чтобы уведомления реально приходили)

Поставь галочки по порядку. Пока все 6 не выполнены — что-то где-то молчит.

- [ ] **1. База Neon создана**, pooled `DATABASE_URL` вставлен в Render.
     Проверка: сайт открывается, поиск находит предметы.
- [ ] **2. На сайте: Настройки → «Проверять каждые» = 3 или 5 минут.**
     (Не 15–30 секунд — иначе съест лимит Neon, см. пункт 0.)
- [ ] **3. На сайте: Настройки → поле «Адрес сайта» = твой `https://xxx.onrender.com`, Сохранить.**
     Иначе кнопки «Открыть аукцион» в Telegram ведут в никуда.
- [ ] **4. Telegram-бот создан и привязан** (инструкция в Настройках сайта,
     раздел Telegram): токен вставлен, код получен, Start боту нажат,
     человек появился в списке привязанных, тестовое сообщение дошло.
- [ ] **5. Cron-job создан** и дёргает URL с secret каждые 2–3 минуты.
     Проверка: подожди 10 минут с закрытым сайтом, посмотри «Последнюю проверку».
- [ ] **6. Трекер создан**: Аукцион → предмет → «Следить» → условия → «Запустить слежку».
     Помни: первый запуск трекера молчаливый (запоминает текущие лоты),
     уведомления идут со следующих обновлений, только по новым лотам.

Если Telegram не приходит — иди по чеклисту сверху вниз, обычно дело
в пункте 3 (не вписан адрес) или 5 (cron не настроен, сайт спит).
