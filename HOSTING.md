# AucTracker — пассивный трекинг 24/7, Git и бесплатный хостинг

## 1. Хватит ли бесплатного Neon?

На бесплатном плане Neon два лимита: **0.5 ГБ места на диске** и **100 CU-часов
компьютера в месяц**. Для этого проекта они очень разные по важности.

**Место на диске — не проблема.** Вся база (каталог из ~2500 предметов игры,
трекеры, уведомления, настройки) весит пару мегабайт. 500 МБ хватит на годы
вперёд, даже если накопятся тысячи уведомлений.

**Компьютер-часы — единственное, что нужно настроить правильно.** Здесь есть
важная особенность Neon: бесплатная база автоматически «замораживается»
(scale to zero) после **5 минут без единого запроса**, и это правило нельзя
отключить на бесплатном тарифе. Пока база «спит» — часы не тратятся. Но если
запросы приходят чаще, чем раз в 5 минут, база вообще не успевает уснуть и
работает непрерывно.

Математика:
- Непрерывная работа 24/7 при минимальной мощности ≈ 0.25 CU × 24 ч × 30 дней
  = **180 CU-часов/мес** — это **больше** лимита в 100 часов. Лимит закончится
  примерно за 2–3 недели, и Neon приостановит базу до начала следующего месяца
  (данные при этом не удаляются, просто сайт перестанет отвечать до перезапуска
  месячного лимита).
- Если проверять трекеры **раз в 10 минут** (значение по умолчанию в этом
  проекте), между проверками остаётся достаточно времени, чтобы база успела
  заснуть. Расход получается примерно **60–90 CU-часов/мес** для 4–5 человек —
  укладывается с запасом.

**Вывод:** для 4–5 непостоянных пользователей настроек по умолчанию
(интервал фонового трекинга — 10 минут, тот же интервал у внешнего cron-пинга)
достаточно. Если увидите в консоли Neon (Dashboard → Compute), что часы
расходуются быстрее ожидаемого — увеличьте интервал в Настройках сайта до
15–30 минут.

Что именно в этом проекте обращается к базе и как это оптимизировано:
- Фоновый планировщик проверяет трекеры раз в N минут (настраивается,
  по умолчанию 10) — это основной и единственный регулярный источник нагрузки.
- Пока у кого-то открыта вкладка сайта, браузер обновляет только счётчик на
  экране локально (без обращений к серверу) и запрашивает свежий статус
  сервера лишь один раз, когда обратный отсчёт закончился — а не каждые
  несколько секунд.
- Список лотов на странице аукциона обновляется у пользователя в браузере
  независимо и не обращается к базе — только к игровому API (это не тратит
  лимит Neon).

## 2. Как запушить код на GitHub

Если раньше не работали с git — вот весь путь целиком, команды вводятся в
терминале VS Code (Терминал → Создать терминал).

### Шаг 1. Создайте репозиторий на GitHub
1. Зайдите на [github.com](https://github.com) → войдите в аккаунт (или
   зарегистрируйтесь).
2. Нажмите зелёную кнопку **New** (или «+» → «New repository» вверху справа).
3. Впишите имя, например `auctracker`. Тип — **Private**, если не хотите,
   чтобы код видели посторонние. Ничего не отмечайте (без README, без
   .gitignore — они уже есть в проекте). Нажмите **Create repository**.
4. На следующей странице скопируйте ссылку вида
   `https://github.com/ваш_ник/auctracker.git` (кнопка справа вверху либо
   строка в блоке «…or push an existing repository from the command line»).

### Шаг 2. Отправьте код из VS Code
В терминале, открытом в папке проекта, выполните команды по очереди:

```bash
git init
git add .
git commit -m "Первая версия сайта"
git branch -M main
git remote add origin https://github.com/ВАШ_НИК/auctracker.git
git push -u origin main
```

При первом `git push` Git может попросить войти в GitHub — откроется браузер,
подтвердите вход. Если раньше уже пушили что-то на этот GitHub-аккаунт с этого
компьютера — авторизация не потребуется.

**Важно:** файл `.env` с паролями и ключами в репозиторий не попадёт — он
специально добавлен в `.gitignore`. Секреты (адрес базы, токен бота) задаются
отдельно на хостинге, через переменные окружения (см. ниже).

### Дальнейшие обновления кода
После первого пуша, чтобы отправить новые изменения:
```bash
git add .
git commit -m "Что изменилось"
git push
```
Если сайт размещён на Render — он подхватит изменения и пересоберётся
автоматически при каждом `git push` в ветку `main`.

## 3. Что нужно, чтобы сайт работал пассивно (уведомления даже с выключенным ПК)

Короткий чек-лист сверху вниз — после выполнения всех пунктов уведомления в
Telegram будут приходить сами, без открытого сайта и включённого компьютера:

- [ ] **База данных Neon создана**, `DATABASE_URL` скопирован.
- [ ] **Код загружен на GitHub** (раздел 2 выше).
- [ ] **Сайт развёрнут на Render** (или другом хостинге с постоянно
      запущенным Node.js-процессом — см. подробности ниже).
- [ ] На хостинге заданы переменные окружения: `DATABASE_URL`,
      `EXBO_CLIENT_ID`, `EXBO_CLIENT_SECRET`.
- [ ] Сайт открывается по постоянному адресу (`https://ваш-сайт.onrender.com`).
- [ ] В разделе **Настройки → Сайт и база предметов** вписан этот адрес.
- [ ] В разделе **Настройки → Telegram** подключён бот и привязаны нужные
      Telegram-аккаунты (у каждого человека — свой код).
- [ ] Настроен внешний пинг на **cron-job.org** по ссылке из
      **Настройки → Фоновый трекинг** — это единственный пункт, без которого
      бесплатный хостинг «уснёт» и перестанет проверять трекеры.
- [ ] Создан хотя бы один трекер на вкладке «Трекеры».

Если все пункты выполнены — можно закрывать сайт и выключать компьютер:
сервер на хостинге продолжит работать, будильник cron-job.org не даст ему
уснуть, а планировщик внутри сайта будет сверять аукцион и слать сообщения в
Telegram по расписанию.

## 4. Подробный план бесплатного хостинга (Render + Neon + cron-job.org)

1. **База данных — Neon** (уже сделано, если вы читаете это через сайт).
   `DATABASE_URL` в разделе Connection Details на neon.tech.
2. **Код — GitHub** (раздел 2 этого файла).
3. **Сайт — Render** (render.com, бесплатно, без карты):
   - New → Web Service → Build and deploy from a Git repository → выбрать
     репозиторий.
   - Build Command: `npm install && npm run build`
   - Start Command: `npm start`
   - Instance Type: **Free**
   - Environment → добавить `DATABASE_URL`, `EXBO_CLIENT_ID` (4062),
     `EXBO_CLIENT_SECRET` (bcoEmyJYSCDarPliHZ0SNOkZscVDCkP0twxPwfLU)
   - Create Web Service, дождаться сборки (3–5 минут). Таблицы в базе
     создадутся автоматически при первом запросе.
4. **Будильник — cron-job.org** (бесплатно, регистрация по email):
   - Ссылку для пинга скопируйте на сайте: Настройки → Фоновый трекинг.
   - Create cronjob → вставить ссылку → интервал «Every 10 minutes» → Save.
   - Это решает сразу две задачи: не даёт Render уснуть (лимит бесплатного
     плана — 15 минут без посетителей) и запускает проверку трекеров.
5. Вернуться на сайт, указать его адрес и привязать Telegram — готово.

### Альтернативы, если что-то не подошло
- **Supabase** вместо Neon — тоже бесплатный Postgres, другие лимиты и правила
  «засыпания» проекта при полном отсутствии активности неделями.
- **Railway** вместо Render — похожий бесплатный план для веб-сервисов.
- **Свой компьютер/сервер (VPS).** Если есть машина, которая и так работает
  24/7 (Raspberry Pi, старый ноутбук, недорогой VPS) — не нужен ни Render, ни
  cron-пинг:
  ```bash
  npm install
  npx drizzle-kit push
  npm run build
  npm start
  ```
  Для автозапуска и перезапуска при сбоях удобен `pm2`:
  ```bash
  npm install -g pm2
  pm2 start npm --name auctracker -- start
  pm2 save
  pm2 startup
  ```
  В этом случае можно смело уменьшать интервал фонового трекинга до 1–2 минут
  в Настройках — лимитов Neon это не касается, если вы используете свою базу
  Postgres, а не бесплатный Neon.

## 5. Переменные окружения

| Переменная           | Обязательно | Где взять                                             |
|-----------------------|-------------|--------------------------------------------------------|
| `DATABASE_URL`        | да          | Neon → Connection Details (или своя Postgres)          |
| `EXBO_CLIENT_ID`      | да          | Уже встроено значение по умолчанию (4062)               |
| `EXBO_CLIENT_SECRET`  | да          | Уже встроено значение по умолчанию                      |
| `TELEGRAM_BOT_TOKEN`  | нет         | Удобнее вставить в сайте: Настройки → Telegram          |

Секрет для ссылки cron-пинга создаётся автоматически и хранится в базе —
смотрите его в Настройках → Фоновый трекинг, там же можно перевыпустить новый.
